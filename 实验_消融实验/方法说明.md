**一句话概括**
这个实验是在评估我们生成的测试用例质量：看这些测试用例是否既能让真实正确提交通过，又能更有效地识别真实错误提交；核心消融点是“加入基于错误解池的 targeted 补测”是否比普通随机/对抗测试更有价值。

**实验目标**
实验使用 TestCase-Eval 中的 Codeforces 原题和真实提交作为外部评测对象。我们的系统先根据题面生成测试输入和标准输出，然后拿 TestCase-Eval 里的真实正确提交、真实错误提交来跑这些测试。

它要回答两个问题：

1. 生成的测试用例是否可靠
   真实正确提交应该尽量通过，避免误杀正确程序。
2. 生成的测试用例是否有覆盖能力
   真实错误提交应该尽量被拒绝，说明测试能暴露程序缺陷。

**实验流程**
整体流程是：

1. 从 TestCase-Eval 选取满足条件的题目和 Python 3 / PyPy 3 提交。
2. 对每道题进行四元组抽取，提取输入结构、核心约束、目标和不变量。
3. 基于题目信息生成测试用例，包括 random、adversarial、small challenge / corner 等类型。
4. 生成或验证标准输出，确保测试用例可执行、可判定。
5. 构造不同实验组的测试套件。
6. 用真实正确提交和真实错误提交分别运行这些测试套件。
7. 统计正确性、覆盖率和消融增益。

**实验组设计**
本实验有三个组：

| 实验组                   | 含义                                                                                       | 目的                                               |
| ------------------------ | ------------------------------------------------------------------------------------------ | -------------------------------------------------- |
| `unicode_style_baseline` | 基础测试集，包含 random、adversarial、small_challenge/corner，不含 targeted 用例           | 作为普通测试生成方法的基线                         |
| `ours_pipeline`          | 在 baseline 基础上加入基于错误解池生成的 targeted 补测                                     | 验证 targeted 补测是否能额外发现错误提交           |
| `size_control`           | 不使用 targeted，而是额外生成普通 random/adversarial 用例，使测试数量与 ours_pipeline 接近 | 排除“只是因为测试用例更多所以覆盖率更高”的混杂因素 |

关键点是：`size_control` 很重要。它让论文里可以说明，如果 `ours_pipeline` 优于 `size_control`，那收益更可能来自 targeted 测试的针对性，而不是单纯来自测试数量增加。

**评估指标**
可以这样解释指标：

| 指标                 | 含义                                                             |
| -------------------- | ---------------------------------------------------------------- |
| `Correctness`        | 真实正确提交的通过率，越高说明测试越不容易误杀正确程序           |
| `Coverage`           | 真实错误提交被拒绝的比例，越高说明测试越能抓住错误程序           |
| `SemanticCoverage`   | 排除运行错误、超时、内存超限等非语义失败后，对错误答案的拦截率   |
| `TargetedGain`       | `ours_pipeline`相比 baseline 的覆盖率提升                        |
| `SizeControlledGain` | `ours_pipeline`相比 size_control 的覆盖率提升                    |
| `CorrectnessDrop`    | 加入 targeted 后正确提交通过率下降多少，用于衡量是否引入误杀风险 |

**论文中可以这样表述**
本实验通过外部真实提交评测生成测试用例的有效性。与只在生成阶段内部验证不同，实验不使用 TestCase-Eval 的提交来构造测试用例，而是将这些提交保留为最终评测对象。正确提交用于衡量测试集的可靠性，错误提交用于衡量测试集的错误发现能力。实验进一步设置等规模控制组，以区分 targeted 补测带来的结构性收益和测试数量增加带来的自然收益。
