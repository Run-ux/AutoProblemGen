# 活跃窗口调配问题

> 生成任务：`inverse_irresponsible_min_edit` / theme `campus_ops`

## 题目描述

校务服务中心最近推出了一项新制度：每天都会根据窗口编号的繁忙程度来动态分配工作人员。

窗口的编号都是正整数。如果一个窗口编号的十进制表示中，至少有一位数字大于或等于 5，我们就称这个窗口是“活跃窗口”；否则称为“普通窗口”。活跃窗口需要额外的服务支持，因此准确预测它们的数量非常重要。

服务中心的领导有一个很有趣的想法：他们想通过“拼接编号”的方式，模拟出一个庞大的排队场景。具体来说，先选定一个基础编号 x（一个不含前导零的十进制字符串），然后把它重复 n 次，首尾相接，得到的巨大整数记作 S。例如 x = "12"，n = 3，则 S = 121212。

他们会把 S 当作一个上界，统计从 1 到 S（包含两端）的所有整数中，活跃窗口到底出现了多少次。这个总数我们用 F(x, n) 来表示。

领导觉得，如果可以微调基础编号 x（修改其中的一些数字位），就能让活跃窗口的总数刚好等于某个预先指定的目标值 T，从而合理地分配人力。每次修改可以选择 x 的任意一位数字，把它变成 0～9 中的另一个数字，但第一位数字不能变成 0（否则 x 的长度就变了，这不符合规定）。每修改一位，就算作 1 次操作。

现在，给定初始的基础编号 x、重复次数 n 以及目标活跃窗口总数 T，请你帮忙计算：最少需要修改多少位数字，才能使得修改后的 x′ 满足 F(x′, n) = T。如果无论如何修改都无法恰好达到 T，请输出 -1。

## 输入格式

输入共两行。
第一行包含两个空格分隔的内容：一个十进制字符串 x，表示初始的基础编号（长度至少为 1，且第一位不是 '0'），以及一个正整数 n，表示重复次数。
第二行包含一个十进制字符串 T，表示目标活跃窗口总数。

## 输出格式

输出一个整数。如果可以通过修改 x 的若干位数字，使得 F(x′, n) = T 恰好成立，则输出所需的最小修改次数；否则输出 -1。

## 数据范围与限制

- 设 L 为 x 的长度。1 ≤ L ≤ 1,000,000。
- 1 ≤ n ≤ 10^18。
- 0 ≤ T ≤ 最大可能的 F 值，T 以十进制字符串形式给出，其数值可能超过 64 位整数范围。
- 时间限制：3 秒。
- 空间限制：512 MB。

### 样例 3

**输入**

```text
1 1
5
```

**输出**

```text
1
```

**说明**

初始 F(1,1)=0。将 x 的个位 '1' 改为 '9'，得到 x′=9，此时 S=9，1～9 中活跃窗口为 5,6,7,8,9 共 5 个，恰好达到目标。只修改 1 位，故输出 1。

### 样例 4

**输入**

```text
9 1
6
```

**输出**

```text
-1
```

**说明**

x 的长度固定为 1，最大可能改为 9，此时 F(9,1)=5。目标 T=6 永远无法达到，因此输出 -1。
