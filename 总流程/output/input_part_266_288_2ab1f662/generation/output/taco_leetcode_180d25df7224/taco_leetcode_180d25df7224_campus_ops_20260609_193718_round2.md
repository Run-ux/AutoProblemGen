# 协调社区预约时间

> 生成任务：`taco_community_001` / theme `community_services`

## 题目描述

在智慧社区中，两个住户 A 和 B 分别提交了一个公共设施（如共享厨房）的预约编码，用来表示他们希望使用的无限重复的时间序列。
每个预约编码是一个字符串，格式为：
<日期部分> [ . <非循环部分> [ ( <循环部分> ) ] ]
其中：
- <日期部分>：长度 1 到 4 的数字串，表示起始日期，不能有两个及以上的连续前导零；
- <非循环部分>：长度 0 到 4 的数字串，可以省略；
- <循环部分>：长度 1 到 4 的数字串，用一对圆括号括起来，也可以省略（若省略，表示有限小数）。
编码代表的实际时间序列定义为：把日期部分当成整数，剩余部分按无限小数展开：先展开 .<非循环部分>，然后无限重复<循环部分>（如果存在）。例如 “3.14(159)” 表示从第 3 天开始，时间戳依次为 3.14159159159… 的无限序列。

由于两个住户可能想占用同一个时间点，社区管理员希望通过修改预约编码中的数字（仅允许将数字字符 ‘0’-‘9’ 修改为其他数字），使修改后的两个编码代表完全相同的时间序列。小数点、左右括号必须保持原样，且任何字符都不能添加、删除或移动位置。每修改一个数字，协商成本增加 1。

你的任务是：计算使两个编码达到数值相等所需的最小总修改次数，并输出一种达到该最小代价的修改方案（即修改后的字符串 S' 和 T'）。

## 输入格式

输入包含两行，每行一个字符串，分别表示住户 A 和住户 B 的原始预约编码。

## 输出格式

第一行输出一个整数，表示最小修改总代价。
接下来两行分别输出修改后住户 A 的编码 S' 和住户 B 的编码 T'。如果存在多组达到最小代价的方案，输出任意一组即可。

## 数据范围与限制

- 输入字符串满足题目所述的预约编码格式，且各部分长度满足：1 ≤ |日期部分| ≤ 4，0 ≤ |非循环部分| ≤ 4，1 ≤ |循环部分| ≤ 4（仅当包含循环部分时）。
- 所有数字字符均为 ‘0’-‘9’，分隔符为 ‘.’ 、 ‘(’ 、 ‘)’ 。
- 时间限制：2秒
- 空间限制：256 MB

## 样例

### 样例 1

**输入**

```text
0.(52)
0.5(25)
```

**输出**

```text
0
0.(52)
0.5(25)
```

**说明**

两个编码原本就表示相同的时间序列（0.525252…），无需修改任何数字。

### 样例 2

**输入**

```text
0.0(9)
1.0
```

**输出**

```text
1
0.9(9)
1.0
```

**说明**

原始编码 0.0(9) 表示 0.0999… = 0.1，而 1.0 表示 1，它们不相等。将第一个编码的非循环部分 ‘0’ 改为 ‘9’ 得到 0.9(9)，它表示 0.999… = 1，与 1.0 相等。仅修改 1 个数字，是最小代价。

### 样例 3

**输入**

```text
0.1(6)
0.3
```

**输出**

```text
2
0.2(9)
0.3
```

**说明**

0.1(6) 表示 0.1666…，0.3 表示 0.3，不相等。将第一个编码的数字 ‘1’ 改为 ‘2’，‘6’ 改为 ‘9’ 得到 0.2(9)，它表示 0.2999… = 0.3。修改 2 个数字，达到了最小代价。

## 说明

输出任意一组最小代价方案都被接受；如果原始编码已经相等，可以直接输出原串。本题保证至少存在一种修改方案（例如将所有数字改为合适的值）使得两个字符串相等。
