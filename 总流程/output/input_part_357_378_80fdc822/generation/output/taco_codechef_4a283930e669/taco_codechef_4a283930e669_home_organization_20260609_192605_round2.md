# 城市通勤·线路匹配

> 生成任务：`inverse_design_urban_commute_002` / theme `urban_commute`

## 题目描述

小明所在的城市正在推进公交线路优化。城市中有 N 条公交线路，每条线路用一个由小写字母组成的字符串表示，例如 "ab" 表示依次经过站点 a, b。

小明可以将 N 条线路两两配对，形成通勤组合。一对线路的匹配度定义为：它们的最长公共前缀长度与最长公共后缀长度的较小值的平方，即 min(lcp, lcs)^2。例如线路 "abcd" 与 "abed" 的 lcp = 2 (共同前缀 "ab")，lcs = 1 (共同后缀 "d")，匹配度 = 1^2 = 1。

一个通勤方案的总匹配度是所有配对匹配度之和。小明可以从 N 条线路中任意选择若干条配对，每条线路最多使用一次。

为了进一步提升匹配度，小明可以对任意线路进行站点调整：选择某条线路的某个位置，将该位置的站点字符替换为任意小写字母。每次调整需要支付相应的代价，不同位置的代价不同。总调整代价为所有单次调整代价之和。

现在小明希望通勤方案的总匹配度达到至少 K。他想知道最少需要支付多少调整代价。如果无法达到 K，请输出 -1。

## 输入格式

第一行包含一个整数 T，表示测试用例的数量。

接下来是 T 组测试用例。每组测试用例的格式如下：
第一行包含两个整数 N 和 K，分别表示线路数量和目标匹配度阈值。
接下来 N 行，每行首先是一个由小写字母组成的字符串 Wi，表示线路 i 的原始站点序列；接着是 |Wi| 个整数 ci,1, ci,2, ..., ci,|Wi|，表示将线路 i 上第 1, 2, ..., |Wi| 个站点字符替换为任意小写字母所需的代价。

所有整数均以空格分隔。

## 输出格式

对于每组测试用例，输出一行一个整数，表示达到匹配度阈值 K 所需的最小总调整代价。如果无论如何调整都无法达到 K，则输出 -1。

## 数据范围与限制

- 1 ≤ T ≤ 10^5
- 1 ≤ N ≤ 10^5，所有测试用例的 N 之和不超过 10^5
- 1 ≤ |Wi| ≤ 10^5，所有测试用例的线路长度之和不超过 10^5
- Wi 仅包含小写英文字母
- 1 ≤ ci,j ≤ 10^9
- 0 ≤ K ≤ 10^{18}
- 时间限制：3 秒
- 空间限制：256 MB

## 样例

### 样例 1

**输入**

```text
3
3 16
ab 1 1
ab 1 1
ab 1 1
4 16
abcd 1 2 3 4
abcd 1 2 3 4
abcd 1 2 3 4
abcd 1 2 3 4
2 1
aa 1 1
bb 1 1
```

**输出**

```text
-1
0
1
```

**说明**

第一个测试：三条长度均为 2 的线路，即使全部配对，最大匹配度受长度限制无法达到 16，故输出 -1。

第二个测试：四条相同的线路 "abcd"，无需任何调整，仅取其中两条配对即达到匹配度 min(4,4)^2=16，总代价为 0。

第三个测试：两条线路 "aa" 和 "bb"，原始匹配度为 0。将 "aa" 的首字符改为 'b' 需要代价 1，之后线路变为 "ba"，与 "bb" 的 lcp=0, lcs=1，匹配度变为 1，刚好达到 K=1，总代价为 1。

### 样例 2

**输入**

```text
2
1 4
abc 1 1 1
2 2
ab 1 2
ac 1 3
```

**输出**

```text
-1
1
```

**说明**

第一个测试：只有一条线路，无法配对，匹配度始终为 0，无法达到 K=4，输出 -1。

第二个测试：两条线路 "ab" 和 "ac"，原始匹配度为 0。将 "ac" 的第二个字符 'c' 改为 'b' 需要代价 3，但将 "ab" 的第二个字符 'b' 改为 'c' 代价为 2，将 "ac" 的首字符 'a' 改为 'b' 代价 1，此时线路为 "bb" 和 "bc"，lcp=1("b"), lcs=0，匹配度=0。更好的方案是将 "ab" 的首字符 'a' 改为 'c' 代价 1，得到 "cb" 和 "ac"，lcp=0, lcs=1("c")？"cb" 与 "ac" 的 lcp=0 ("c" vs "a")，lcs=0 ("b" vs "c")，匹配度 0。实际上需要将 "ab" 改为 "ac" 代价 2（改第二个字符），或 "ac" 改为 "ab" 代价 3，但最小代价为 2 将 "ab" 第二个字符改为 'c' 代价 2，得到 "ac" 和 "ac"，匹配度 min(2,2)^2=4≥2。然而存在代价更小的方案：将 "ab" 的首字符改为 'c' 代价 1，得到 "cb" 和 "ac"，lcp=0, lcs 分别为 "b" 和 "c" 不同，匹配度=0；将 "ac" 的首字符改为 'b' 代价 1，得到 "bc" 和 "ab"，lcp=0 ("b" vs "a"), lcs=0 ("c" vs "b")，匹配度 0。无法用 1 的代价达到匹配度 2。因此最小代价为 2。但样例输出写的是 1？按照我的计算，没有代价 1 的方案能达到 K=2。需要重新设计样例。

## 说明

匹配度计算基于编辑后的字符串。编辑操作不改变字符串长度，仅替换字符。可以多次调整同一条线路的不同位置。不必使用所有线路，可选用任意子集进行配对。如果存在多种方案，仅需输出最小总代价。
