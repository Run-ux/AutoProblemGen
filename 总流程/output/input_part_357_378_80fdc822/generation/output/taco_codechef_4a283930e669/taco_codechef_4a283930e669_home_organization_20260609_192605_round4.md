# 城市通勤·线路匹配

> 生成任务：`inverse_design_urban_commute_002` / theme `urban_commute`

## 题目描述

小明所在的城市正在推进公交线路优化。城市中有 N 条公交线路，每条线路用一个由小写字母组成的字符串表示，例如 "ab" 表示依次经过站点 a, b。

小明可以将线路两两配对形成通勤组合。一对线路的匹配度定义为：它们的最长公共前缀长度与最长公共后缀长度的较小值的平方，即 min(lcp, lcs)^2。例如线路 "abcd" 与 "abed" 的 lcp = 2（共同前缀 "ab"），lcs = 1（共同后缀 "d"），匹配度 = 1^2 = 1。

一个通勤方案的总匹配度是所有配对匹配度之和。小明可以从 N 条线路中任意选择若干条配对，每条线路最多使用一次。

为了进一步提升匹配度，小明可以调整线路：选择某条线路的某个位置，将该位置的站点字符替换为任意小写字母。每次调整需要支付相应的代价，不同位置的代价不同。同一条线路的多个位置可以分别进行调整，总调整代价为各次调整代价之和。

现在小明希望通勤方案的总匹配度达到至少 K。他想知道最少需要支付多少调整代价。如果无论如何调整都无法达到 K，请输出 -1。

## 输入格式

第一行包含一个整数 T，表示测试用例的数量。

接下来是 T 组测试用例。每组测试用例的格式如下：
第一行包含两个整数 N 和 K，分别表示线路数量和目标匹配度阈值。
接下来 N 行，每行首先是一个由小写字母组成的字符串 Wi，表示线路 i 的原始站点序列；接着是 |Wi| 个整数 ci,1, ci,2, ..., ci,|Wi|，表示将线路 i 上第 1, 2, ..., |Wi| 个站点字符替换为任意小写字母所需的代价。

所有整数均以空格分隔。

## 输出格式

对于每组测试用例，输出一行一个整数，表示达到匹配度阈值 K 所需的最小总调整代价。如果无论如何调整都无法达到 K，则输出 -1。

## 数据范围与限制

- 1 ≤ T ≤ 10^5，所有测试用例的 N 之和不超过 10^5
- 1 ≤ N ≤ 10^5
- 1 ≤ |Wi| ≤ 10^5 ，所有测试用例的线路长度之和不超过 10^5
- Wi 仅包含小写英文字母
- 1 ≤ ci,j ≤ 10^9
- 0 ≤ K ≤ 10^18
- 时间限制：3 秒
- 空间限制：256 MB

## 样例

### 样例 1

**输入**

```text
3
3 16
ab 1 1
ab 1 1
ab 1 1
4 16
abcd 1 2 3 4
abcd 1 2 3 4
abcd 1 2 3 4
abcd 1 2 3 4
2 1
a 1
b 1
```

**输出**

```text
-1
0
1
```

**说明**

第一个测试用例：三条线路长度均为2，任意两条配对的匹配度为 min(2,2)^2=4，总和最多为4，无法达到 K=16，因此输出 -1。
第二个测试用例：四条相同的线路 "abcd"，直接取其中两条配对，匹配度 min(4,4)^2=16，达到 K=16，总代价为 0。
第三个测试用例：原始两条线路 "a" 和 "b" 的匹配度为 0。将 "a" 改为 "b"，代价为 1，得到 "b"。编辑后的 "b" 与 "b" 配对，最长公共前缀和最长公共后缀长度均为 1，匹配度为 min(1,1)^2=1，达到 K=1，总代价为 1。

### 样例 2

**输入**

```text
2
2 4
ab 1 100
ac 100 1
2 4
ab 1 2
ba 3 4
```

**输出**

```text
1
3
```

**说明**

第一个测试用例：原始匹配度为 0。将 "ac" 的第二个字符改为 'b'，代价为 1，得到 "ab"。编辑后的 "ab" 与未编辑的 "ab" 配对，匹配度为 min(2,2)^2=4，达到 K=4，总代价为 1。
第二个测试用例：原始匹配度为 0。将 "ab" 的第一个字符改为 'b'（代价 1），第二个字符改为 'a'（代价 2），总代价为 3，得到 "ba"。编辑后的 "ba" 与未编辑的 "ba" 配对，匹配度为 min(2,2)^2=4，达到 K=4。其他编辑方案代价均不小于 3，因此最小代价为 3。

## 说明

匹配度计算基于编辑后的字符串。编辑操作仅替换字符，不改变字符串长度。同一条线路的不同位置可以分别进行调整。不必使用所有线路，可选用任意子集进行配对，保证每条原始线路最多被使用一次。如果 K=0，可以不进行任何配对，总代价为 0。
