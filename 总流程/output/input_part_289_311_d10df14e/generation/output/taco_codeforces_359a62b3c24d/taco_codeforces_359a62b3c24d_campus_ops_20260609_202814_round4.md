# 储物柜整理挑战

> 生成任务：`inv_home_organization_target_cost` / theme `home_organization`

## 题目描述

小明正在整理他的储物柜，柜子里有 n 件物品。每件物品有两个属性：占用格子数 ti 和整理费用 ci。ti 是一个非负整数，ci 是一个正整数。

小明可以选择一些物品并支付它们的整理费用。只要所有被支付物品的总占用格子数不少于未被支付物品的数量，他就能成功整理所有物品。换句话说，对于一个支付集合 P，必须满足 ∑_{i∈P} ti ≥ n - |P|，此时总支付为 ∑_{i∈P} ci。

然而，今天小明希望先调整这些物品的属性，使得在后续的最优整理方案中，最小总支付恰好等于指定的目标 K。他可以对每件物品进行修改：将占用格子数改为 0 到 2000 之间的任意整数 new_ti，将整理费用改为 1 到 10^9 之间的任意整数 new_ci。每次修改的代价为 |new_ti - ti| + |new_ci - ci|。总修改代价是所有单件物品修改代价之和。

请判断是否存在一种修改方案，使得修改后的物品集合在最优整理策略下（即满足覆盖约束并使总支付最小）的最小支付恰好等于 K。如果存在，请输出最小的总修改代价，并给出一种具体的修改方案；如果不可能，则输出 -1。

## 输入格式

第一行一个整数 n (1 ≤ n ≤ 2000)，表示物品的数量。
接下来 n 行，每行两个整数 ti, ci (0 ≤ ti ≤ 2000, 1 ≤ ci ≤ 10^9)，描述每件物品原始的占用格子数和整理费用。
最后一行一个整数 K (1 ≤ K ≤ 10^9)，表示目标最小总支付。

## 输出格式

如果无法通过修改使得最小支付恰好为 K，只输出一个整数 -1。
否则，第一行输出一个整数，表示最小的总修改代价。
接下来 n 行，每行输出两个整数 new_ti, new_ci，表示第 i 件物品修改后的占用格子数和整理费用。若有多种最优修改方案，输出任意一种即可。

## 数据范围与限制

- 时间限制：2 秒
- 空间限制：256 MB
- 1 ≤ n ≤ 2000
- 0 ≤ ti ≤ 2000，1 ≤ ci ≤ 10^9
- 1 ≤ K ≤ 10^9
- 修改后的 new_ti 必须满足 0 ≤ new_ti ≤ 2000，new_ci 必须满足 1 ≤ new_ci ≤ 10^9

## 样例

### 样例 1

**输入**

```text
1
0 5
5
```

**输出**

```text
0
0 5
```

**说明**

只有一件物品，占用格子数为 0，整理费用为 5。由于 n=1，覆盖条件为 ti ≥ 0，任意子集均满足，因此最小支付即为该物品的费用 5，恰好等于目标 K=5。不需要任何修改，总代价为 0，输出原始属性即可。

### 样例 2

**输入**

```text
2
2 10
0 20
8
```

**输出**

```text
24
0 1
0 7
```

**说明**

有两件物品，原始属性为 (2,10) 和 (0,20)，目标 K=8。若不做修改，第一件物品单独即可满足 ∑ti=2 ≥ 1，因此最小支付为 10，不为 8。为了让最小支付恰好为 8，必须使任何单件物品都不能单独满足条件，即 new_t1 和 new_t2 都必须为 0。这样，唯一满足覆盖条件的子集是全集 {1,2}，其总费用必须等于 8。一种代价最小的修改方案是将第一件改为 (0,1)，第二件改为 (0,7)，总修改代价为 |0-2|+|1-10| + |0-0|+|7-20| = 2+9+0+13 = 24。可以证明不存在总代价更小的方案。

### 样例 3

**输入**

```text
3
3 5
1 8
0 2
7
```

**输出**

```text
2
3 7
1 8
0 2
```

**说明**

有三件物品，原始属性为 (3,5), (1,8), (0,2)，目标 K=7。原始最小支付为 5（只支付第一件即可，因为 3 ≥ 3-1=2）。要使最小支付变为 7，最经济的做法是将第一件物品的费用提高到 7，其他属性不变。此时支付第一件的费用为 7，而其他子集（如仅支付第三件，需满足 0 ≥ 3-1=2，不成立）均不可行，因此最小支付恰好为 7。总修改代价为 |7-5| = 2。不存在比 2 更小的修改代价。

## 说明

请注意答案可能超出 32 位整数范围，建议使用 64 位整数类型。如果存在多种最优修改方案，输出任意一种即可。
