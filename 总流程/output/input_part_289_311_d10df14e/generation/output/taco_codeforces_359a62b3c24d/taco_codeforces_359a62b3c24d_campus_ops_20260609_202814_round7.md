# 储物柜整理挑战

> 生成任务：`inv_home_organization_target_cost` / theme `home_organization`

## 题目描述

小明有一排储物柜，共有 n 个格子。他想整理里面存放的 n 件物品。每件物品 i 有两个属性：占用格子数 ti（非负整数）和整理费用 ci（正整数）。整理时，他可以选择一个子集 P 并支付这些物品的费用。只要支付物品的总占用格子数不少于未支付物品的数量，就能完成整理。即必须满足 ∑_{i∈P} ti ≥ n - |P|，此时总支付为 ∑_{i∈P} ci。小明会对这些物品进行最优整理，即选择满足条件的子集使总支付最小。

然而，在整理前，小明可以修改物品的属性：对于第 i 件物品，他可以将 ti 改为任意在 [0,2000] 内的整数 new_ti，将 ci 改为任意在 [1,10^9] 内的整数 new_ci。每次修改的代价定义为 |new_ti - ti| + |new_ci - ci|，总修改代价为各物品修改代价之和。

他希望最终修改后的物品集合，在最优整理下的最小支付恰好等于一个给定的目标值 K。请判断是否可行？若可行，输出最小的总修改代价，并给出一种具体的修改方案；若不可能，输出 -1。

## 输入格式

第一行一个整数 n (1 ≤ n ≤ 2000)，表示物品的数量。
接下来 n 行，每行两个整数 ti, ci (0 ≤ ti ≤ 2000, 1 ≤ ci ≤ 10^9)，描述每件物品原始的占用格子数和整理费用。
最后一行一个整数 K (1 ≤ K ≤ 10^9)，表示目标最小总支付。

## 输出格式

如果无法通过修改使得最小支付恰好为 K，只输出一个整数 -1。
否则，第一行输出一个整数，表示最小的总修改代价。
接下来 n 行，每行输出两个整数 new_ti, new_ci，表示第 i 件物品修改后的占用格子数和整理费用。若有多种最优修改方案，输出任意一种即可。

## 数据范围与限制

- 时间限制：2 秒
- 空间限制：256 MB
- 1 ≤ n ≤ 2000
- 0 ≤ ti ≤ 2000
- 1 ≤ ci ≤ 10^9
- 1 ≤ K ≤ 10^9
- 修改后的 new_ti 必须在 [0, 2000] 内
- 修改后的 new_ci 必须在 [1, 10^9] 内

## 样例

### 样例 1

**输入**

```text
1
0 5
5
```

**输出**

```text
0
0 5
```

**说明**

只有一件物品，必须支付它（空子集不满足覆盖条件）。支付该物品后，覆盖条件 ti≥0 恒成立，最小支付即为 5，恰好等于 K=5。无需任何修改，总修改代价为 0，输出原始属性即可。

### 样例 2

**输入**

```text
2
2 10
0 20
8
```

**输出**

```text
24
0 1
0 7
```

**说明**

有两件物品，原始属性为 (2,10) 和 (0,20)，目标 K=8。若不做修改，第一件物品单独即可满足 ∑ti=2 ≥ 1，最小支付为 10，不为 8。为了让最小支付恰好为 8，必须使任何单件物品都不能单独满足条件，即 new_t1 和 new_t2 都必须为 0。这样，唯一满足覆盖条件的子集是全集 {1,2}，其总费用必须等于 8。一种代价最小的修改方案是将第一件改为 (0,1)，第二件改为 (0,7)，总修改代价为 |0-2|+|1-10| + |0-0|+|7-20| = 2+9+0+13 = 24。可以证明不存在总代价更小的方案。

### 样例 3

**输入**

```text
3
3 5
1 8
0 2
7
```

**输出**

```text
2
3 7
1 8
0 2
```

**说明**

有三件物品，原始属性为 (3,5), (1,8), (0,2)，目标 K=7。原始最小支付为 5（只支付第一件，因为 3 ≥ 3-1=2）。要使最小支付变为 7，最经济的做法是将第一件物品的费用提高到 7，其他属性不变。此时支付第一件的费用为 7，而其他子集（如仅支付第三件，需满足 0 ≥ 3-1=2，不成立）均不可行，因此最小支付恰好为 7。总修改代价为 |7-5| = 2。不存在比 2 更小的修改代价。

## 说明

可以证明对于所有满足数据范围的 K，总是存在可行的修改方案，实际测试数据中不会出现需要输出 -1 的情况。但仍然建议按照输出格式处理 -1 的输出。注意答案可能超过 32 位整数范围，请使用 64 位整数类型。如果有多组最优方案，任意输出一组即可。
