# 储物柜整理挑战

> 生成任务：`inv_home_organization_target_cost` / theme `home_organization`

## 题目描述

小明正在整理他的储物柜。柜子里有 n 件物品，每件物品用一个非负整数 ti 表示它占用的格子数，以及一个正整数 ci 表示整理它需要支付的费用。

小明可以选定一些物品并支付它们的整理费用。只要所有被支付物品的总占用格子数不少于未被支付物品的数量，他就可以顺利地把所有物品都整理好。换句话说，如果被支付的物品集合为 P，那么必须满足 ∑_{i∈P} ti ≥ n - |P|。此时小明支付的总费用就是 ∑_{i∈P} ci。

然而，今天小明想先调整这些物品的属性，以便在后续的最佳整理方案中恰好需要支付 K 元。对于第 i 件物品，他可以将其占用格子数修改为任意非负整数 new_ti，整理费用修改为任意正整数 new_ci，但每次修改都会产生代价：占用格子数每变化 1（取绝对值）产生 1 的代价，整理费用每变化 1 也产生 1 的代价。因此，修改第 i 件物品的总代价为 |new_ti - ti| + |new_ci - ci|。

小明希望知道：是否存在一种修改方案，使得修改后的物品集合在最优整理策略下的最小总支付恰好等于 K？如果存在，他想要最小化所有物品修改的总代价，并给出一种修改方案；如果不可能，请告诉他无法达成。

## 输入格式

第一行一个整数 n (1 ≤ n ≤ 2000)，表示物品的数量。
接下来 n 行，每行两个整数 ti, ci (0 ≤ ti ≤ 2000, 1 ≤ ci ≤ 10^9)，描述每件物品原始的占用格子数和整理费用。
最后一行一个整数 K (1 ≤ K ≤ 10^9)，表示目标最小总支付。

## 输出格式

如果无法通过修改使得最小支付恰好为 K，只输出一个整数 -1。
否则，第一行输出一个整数，表示最小的总修改代价。
接下来 n 行，每行输出两个整数 new_ti, new_ci，表示第 i 件物品修改后的占用格子数和整理费用。如果有多种最优修改方案，输出任意一种即可。

## 数据范围与限制

- 时间限制：2 秒
- 空间限制：256 MB

## 样例

### 样例 1

**输入**

```text
1
0 5
5
```

**输出**

```text
0
0 5
```

**说明**

只有一件物品，占用格子数为 0，整理费用为 5。由于 n=1，必须满足 ∑ti ≥ 0，任何子集都满足，因此最小支付就是该物品的费用 5，恰好等于目标 K=5。不需要任何修改，总代价为 0，输出原属性即可。

### 样例 2

**输入**

```text
2
2 10
0 20
8
```

**输出**

```text
24
0 1
0 7
```

**说明**

有两件物品，原始属性为 (2,10) 和 (0,20)，目标 K=8。若不做修改，第一件物品单独即可满足 ∑ti=2≥1，因此最小支付为 10，不等于 8。为了让最小支付恰好为 8，必须使任何单件物品都不能单独满足条件，即 new_t1 和 new_t2 都必须为 0。这样，唯一满足条件的子集是全集 {1,2}，其总费用必须等于 8。一种代价最小的修改方案是将第一件改为 (0,1)，第二件改为 (0,7)，总修改代价为 |0-2|+|1-10| + |0-0|+|7-20| = 2+9+0+13 = 24。可以证明不存在总代价更小的方案。

## 说明

所有数据均为整数。修改时 new_ti 可以为任意非负整数，new_ci 可以为任意正整数。若有多组最优修改方案，输出任意一组即可。请注意答案可能超出 32 位整数范围，建议使用 64 位整数类型。
