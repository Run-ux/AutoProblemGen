# 公交好度调度

> 生成任务：`canonical_witness_urban_commute_medmax` / theme `urban_commute`

## 题目描述

在城市公交系统中，有 n 条公交线路，每条线路停靠 n 个站点。每个站点有一个舒适度评分（正整数）。作为调度员，你可以将所有给出的 n×n 个评分重新分配到任意线路的任意站点上，并且每条线路上的站点顺序可以任意排列。

对于一条线路，定义它的正点指数为该线路上所有站点评分的中位数：将线路上的 n 个评分升序排列后，取第 ⌈(n+1)/2⌉ 小的元素。整个系统的好度定义为所有线路正点指数的最小值。调度的成本定义为所有线路的正点指数之和。由于预算限制，成本不能超过 k。

你需要找出一个调度方案（即 n×n 的评分矩阵），该方案必须同时满足以下两项核心要求：
1. 成本约束：所有线路正点指数之和 ≤ k；
2. 字典序约束：在所有满足成本约束且好度达到最大值的方案中，该矩阵按行优先（从上到下、从左到右）展开后得到的序列字典序最小。

输出该方案所达到的最大好度，以及具体的评分矩阵。如果没有任何安排能满足成本约束，输出 -1。

## 输入格式

第一行包含一个整数 t，表示测试用例的数量。接下来描述每个测试用例：
每个测试用例的第一行包含两个整数 n 和 k，分别表示线路数量（同时也是每条线路的站点数量）和预算上限。
接下来的 n 行，每行包含 n 个整数，表示初始给出的 n×n 个站点舒适度评分（你可以将其任意重排）。

## 输出格式

对于每个测试用例：
- 如果存在满足成本约束的安排，首先输出一行一个整数 G，表示最大可能的好度。然后输出 n 行，每行 n 个整数，表示你安排好的评分矩阵。该矩阵必须满足：
  1. 每行的正点指数（按中位数定义）均 ≥ G；
  2. 所有行的正点指数之和 ≤ k；
  3. 在所有满足上述条件且好度达到 G 的矩阵中，将其按行优先展开成一维数组后，该数组的字典序最小。
- 如果不存在任何满足成本约束的安排，则只输出一行 -1。

## 数据范围与限制

- 1 ≤ t ≤ 100
- 1 ≤ n ≤ 1000
- 所有测试用例的 n 之和 ≤ 1000
- 1 ≤ k ≤ 10^14
- 1 ≤ 舒适度评分 ≤ 10^9
- 时间限制：2 秒
- 空间限制：256 MB

## 样例

### 样例 1

**输入**

```text
1
3 15
1 2 3
4 5 6
7 8 9
```

**输出**

```text
4
1 4 7
2 5 8
3 6 9
```

**说明**

给定的 9 个评分为 1 到 9。要达到好度 5，需要每条线路的正点指数至少为 5。此时至少需要成本为 5+5+6=16，超过预算 15，因此最大好度为 4。
给出的安排方案中，三条线路分别为 [1,4,7]、[2,5,8]、[3,6,9]，正点指数依次为 4、5、6，好度 4，成本 15。将该矩阵按行优先展开得到序列 [1,4,7,2,5,8,3,6,9]。可以证明，在所有好度为 4 且成本 ≤15 的安排中，该序列是字典序最小的。例如，若第一行换成 [1,4,8] 等，都会导致字典序更大。

### 样例 2

**输入**

```text
1
2 1
1 2
3 4
```

**输出**

```text
-1
```

**说明**

n=2，共有 4 个评分。每条线路的站点数为 2，中位数为该线路上评分的较大者，因此两行的正点指数至少为 3+4=7 > 1。预算为 1，无法满足任何安排，故输出 -1。

## 说明

中位数的定义：对于包含 n 个整数的序列，将其升序排序后，第 ⌈(n+1)/2⌉ 个元素即为中位数。例如 n=2 时中位数为较大的元素，n=3 时为第二小的元素，n=4 时为第三小的元素。
字典序比较：将两个矩阵按行优先展开成一维数组，从左到右依次比较对应位置的元素，第一个出现不同元素的位置上，较小者字典序更小；若所有对应位置元素均相同，则两者相等。
若多个安排同时达到最大好度且满足成本约束，必须输出字典序最小的那个。若不存在任何可行安排，输出 -1。
