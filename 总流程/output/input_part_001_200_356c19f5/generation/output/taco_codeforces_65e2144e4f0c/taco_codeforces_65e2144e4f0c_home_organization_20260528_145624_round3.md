# 校园拦截计划

> 生成任务：`campoo_wardrobe_counting_v1` / theme `campus_ops`

## 题目描述

校园活动中心由 n 个房间和 n-1 条走廊连接，形成一棵树。1 号房间是总控室，其他房间中，仅有一条走廊相连的房间称为“安全屋”。

调皮的小明从 1 号房间出发，试图通过移动到达任意一个安全屋。如果他成功进入安全屋，则小明获胜。

学校派出了 k 名志愿者，分别驻守在编号为 x_1, x_2, ..., x_k 的房间（这些房间互不相同，且都不是 1 号房间）。你可以选择让其中一部分志愿者参与拦截行动（其他人休息）。所有被选中的志愿者和小明同时移动：每步可以选择沿着一条走廊移动到相邻房间，或者停留在原地。

如果在小明到达安全屋之前的任意时刻，小明的房间（或正在穿越的走廊）与某位参与行动的志愿者的房间（或走廊）重合（即两人在同一房间，或者在同一时间沿着同一走廊相向而行），则视为拦截成功，志愿者获胜。

你的任务是选择一个参与行动的志愿者子集，使得他们能够确保拦截成功（即无论小明如何移动，志愿者都有策略抓住他）。这样的子集称为可行的。由于人力有限，你希望参与的人数尽可能少。请统计有多少种选择参与者的方案，使得人数达到全局最少，并保证拦截成功。

两个方案不同当且仅当它们选择的志愿者编号集合不同。

由于校园的树形结构，通往不同安全屋的路径可能分叉。我们可以把问题分解为在各个子树中完成拦截的子任务：对于以某个节点为根的子树，我们需要覆盖所有经过该节点到达叶子的路径。这些子树之间是独立的，我们可以在树上自底向上地计算每个节点所需的最小拦截人数及达到该人数的选择方案数，最终在根节点合并得到全局答案。

## 输入格式

第一行包含一个整数 t (1 ≤ t ≤ 10^4)，表示测试用例的数量。
每个测试用例前可能有一个空行。
每个测试用例的第一行包含两个整数 n 和 k (1 ≤ k < n ≤ 2·10^5)，分别表示房间数和志愿者人数。
第二行包含 k 个互不相同的整数 x_1, x_2, ..., x_k (2 ≤ x_i ≤ n)，表示每个志愿者的初始房间。志愿者按照输入顺序编号为 1 到 k。
接下来 n-1 行，每行包含两个整数 u, v (1 ≤ u, v ≤ n)，表示房间 u 和 v 之间有一条走廊。保证给出的图是一棵树。
所有测试用例的 n 之和不超过 2·10^5。

## 输出格式

对于每个测试用例，输出一行一个整数，表示满足条件的方案数对 1,000,000,007 (10^9+7) 取模后的结果。

## 数据范围与限制

- 时间限制：2 秒
- 空间限制：256 MB
- 1 ≤ t ≤ 10^4
- 2 ≤ n ≤ 2·10^5，所有测试用例的 n 之和不超过 2·10^5
- 1 ≤ k < n
- 2 ≤ x_i ≤ n，且 x_i 互不相同
- 给定的边构成一棵树
- 输入数据保证至少存在一个可行的志愿者子集，且 k ≥ 1

## 样例

### 样例 1

**输入**

```text
1
4 3
2 3 4
1 2
2 3
3 4
```

**输出**

```text
3
```

**说明**

树是一条链 1-2-3-4，安全屋为 4。志愿者 1,2,3 分别位于房间 2,3,4。只有一条通往安全屋的路径，任何一位志愿者单独拦截即可：待在原地或在路径上移动，在小明到达安全屋之前一定能相遇。因此，最小需要人数为 1，选择任意一个志愿者均可行，共有 3 种方案。答案为 3。

### 样例 2

**输入**

```text
1
5 3
2 4 5
1 2
1 4
2 3
4 5
```

**输出**

```text
2
```

**说明**

树的结构：1-2-3 和 1-4-5 两条分支，安全屋为 3 和 5。志愿者 1 在房间 2，志愿者 2 在房间 4，志愿者 3 在房间 5。要成功拦截，必须同时防守通往 3 和通往 5 的路径。防守通往 3 的路径需要至少一名在房间 2 的志愿者（也就是志愿者 1）；防守通往 5 的路径可以在房间 4（志愿者 2）或房间 5（志愿者 3）中选择。因此最小总人数为 2，可行的方案为 {1, 2} 和 {1, 3}，共 2 种。答案为 2。

## 说明

方案数可能很大，请输出对 1,000,000,007 取模的结果。两个方案相同当且仅当它们包含的志愿者编号集合完全相同。输入数据保证 k ≥ 1，且至少存在一个可行的志愿者子集，故无需考虑无解的情况。
