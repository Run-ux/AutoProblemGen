# 公交环线改造计划

> 生成任务：`urban_commute_inverse_design_01` / theme `urban_commute`

## 题目描述

市政府计划对现有的公交线路进行改造，以更好地满足市民的通勤需求。城市中有 n 个公交站点，目前有 m 条双向公交线路直接连接两两站点。每条线路都可以双向通行，且当前不存在重复线路，也没有从站点到自身的线路。

经过调查，市民们希望最终的公交网络能够形成一个“主干环线”结构：存在一条唯一的简单环线（即环形主干道），网络中的其余线路都从这条环线向外延伸，形成树枝状结构。更为具体地，市民对每个站点 i 提出了一个期望距离 d_i，表示从站点 i 沿着公交线路到达主干环线的最少经过边数。注意，如果某个站点本身就是环线上的站点，那么它的期望距离为 0。

你作为规划师，可以执行以下两种操作来改造现状：
- 拆除一条现有的线路（代价为 1）；
- 在两个当前没有线路直接相连的站点之间新建一条线路（代价为 1）。

每执行一次操作都会产生 1 单位的总代价。你的目标是找到一系列操作，使得改造后的公交网络满足所有期望距离，同时总代价最小。如果根本不存在满足要求的改造方案，请指出这一点。

## 输入格式

第一行包含两个整数 n, m (3 ≤ n ≤ 3000, 0 ≤ m ≤ n·(n-1)/2)，分别表示站点数量和现有线路数量。站点从 1 到 n 编号。
接下来 m 行，每行包含两个整数 x_i, y_i (1 ≤ x_i, y_i ≤ n, x_i ≠ y_i)，表示当前存在一条直接连接站点 x_i 和 y_i 的线路。保证不存在重边（即任意无序对至多出现一次）。
最后一行包含 n 个整数 d_1, d_2, ..., d_n (0 ≤ d_i ≤ n)，其中 d_i 表示站点 i 的期望距离，含义见题目描述。

## 输出格式

输出一个整数，表示最小的总代价（操作次数）。如果不存在任何合法的改造方案，输出 -1。

## 数据范围与限制

- 时间限制：3.0 秒
- 空间限制：512.0 MB

## 样例

### 样例 1

**输入**

```text
5 2
1 2
4 5
0 0 0 1 1
```

**输出**

```text
4
```

**说明**

最小代价方案：添加线路 (2,3), (3,1), (3,4), (2,5)，最终网络包含 5 个站点和 5 条边，环为 1-2-3-1，站点 4 和 5 分别通过线路 (3,4) 和 (2,5) 连接到环，距离环均为 1。只需添加 4 条边，无需拆除，总代价 4。

### 样例 2

**输入**

```text
3 0
0 0 1
```

**输出**

```text
-1
```

**说明**

距离为 0 的站点只有 2 个，但任何合法网络的环长度至少为 3，故不可能实现。

## 说明

最终网络必须恰好包含 n 条边，连通，且包含恰好一个简单环。所有期望距离必须被严格满足：站点到环的最短经过边数恰好等于 d_i。距离为 0 的站点构成环上的所有站点。若存在多个可行方案，输出最小总代价。如果无论如何都无法满足，请输出 -1。
