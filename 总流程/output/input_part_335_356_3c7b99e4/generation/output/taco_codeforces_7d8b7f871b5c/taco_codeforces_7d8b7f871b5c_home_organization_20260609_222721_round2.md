# 跳蚤市场的公益角落

> 生成任务：`inv_design_tickets_min_modify_lex` / theme `campus_ops`

## 题目描述

学校的跳蚤市场开张啦！有 n 个摊位一字排开，每个摊位都有一个标价 p_i（100 的倍数）。为了让活动更有意义，市场方联合了两个公益项目：「绿色校园」和「爱心助困」。
购买者会依次在 1,2,…,M 个摊位上选购商品。在第 a 的倍数摊位（第 a,2a,3a,… 个）上，成交价的 x% 将捐赠给绿色校园；在第 b 的倍数摊位（第 b,2b,3b,… 个）上，成交价的 y% 将捐赠给爱心助困。若某个摊位同时是两个项目的倍数，则捐赠 (x+y)%。
作为市场管理员，你发现原定的标价序列可能让总捐赠额无法达到目标 k。但你有一个特权：可以调整任意物品的标价（改为另一个 100 的倍数，且必须在 [100,10^9] 内），每调整一次计为一次修改。同时，你还可以任意选择最终出售的 M 件商品，并决定它们的排列顺序。
你希望调整的次数尽可能少，因为频繁改价会惹恼摊主。如果不得不修改，在所有修改次数最少的方案里，你还希望最终展出的 M 个价格序列（按排列顺序）字典序尽可能地大（即从左往右比较，第一个不同的位置数值大者胜出），这样看起来更“诱人”。
请你计算：对于每组查询，最少需要修改几次标价？并在最少修改次数下，输出字典序最大的最终价格序列。如果无论如何都无法让捐赠总额达到 k，请输出 -1。

## 输入格式

第一行一个整数 q (1≤q≤100)，表示查询组数。
接下来依次描述 q 组查询，每组查询格式如下：
第一行一个整数 n (1≤n≤2×10^5)，表示摊位数量。
第二行 n 个整数 p_1,p_2,…,p_n (100≤p_i≤10^9, p_i mod 100=0)，各摊位的初始标价。
第三行两个整数 x 和 a (1≤x≤100, x+y≤100, 1≤a≤n)，第一个公益项目的参数。
第四行两个整数 y 和 b (1≤y≤100, x+y≤100, 1≤b≤n)，第二个公益项目的参数。
第五行一个整数 k (1≤k≤10^14)，目标总捐赠额。
第六行一个整数 M (1≤M≤n)，计划出售的商品数量。
保证所有查询的 n 之和不超过 2×10^5。

## 输出格式

对于每组查询：
若无法达成 k，输出一行 -1。
否则，输出两行：第一行一个整数 c，表示最少修改次数；第二行 M 个整数，表示最终售出商品的标价序列（按购买顺序）。该序列应当保证在修改 c 次后总捐赠额 ≥k，并且字典序最大。

## 数据范围与限制

- 时间限制：2.0 秒
- 空间限制：256 兆字节
- 所有价格均为 100 的倍数，计算捐赠额时不会产生小数
- x+y ≤ 100，保证单件商品最大捐赠比例不超过 100%
- 1 ≤ M ≤ n ≤ 2×10^5，所有查询的 n 总和 ≤ 2×10^5
- 1 ≤ k ≤ 10^14，使用 64 位整数计算总捐赠额

## 样例

### 样例 1

**输入**

```text
1
5
500 100 400 200 300
10 2
20 3
150
4
```

**输出**

```text
0
100 300 400 200
```

**说明**

不用修改任何标价（c=0）。需要售出 M=4 件，捐赠计划：第2、4个摊位捐10%，第3个摊位捐20%。最大捐赠序列为 [100,300,400,200]：100×0% + 300×10% + 400×20% + 200×10% = 0+30+80+20=130 <150，不能满足。但重新排列为 [100,400,200,300] 仍不足。唯一满足的序列是 [100,300,400,200]？尝试将400放第2位得40，300放第3位得60，200放第4位得20，100放第1位得0，合计120。实际上要把最大的400放在权重最高的第3位，300放在第2位，200放在第4位，100放第1位，得到 0+30+80+20=130。还是达不到150。需要寻找满足的排列：若把500放第2位（捐10%得50），400放第3位（捐20%得80），300放第1位（0），200放第4位（捐10%得20），总计150，可行！序列为 [300,500,400,200] 总捐赠10%+20%+10%: 500×0.1=50, 400×0.2=80, 200×0.1=20，共150。字典序比较：[300,500,400,200] 和 [500,300,400,200]？若将500放第1位，第1位权重0，浪费，需用下面位置补，不可能达到150。所以 [300,500,400,200] 是可行的且字典序可能已最大？还有 [400,500,300,200] 第一位置400>300，但若400放第1，后面需用500和300补，最大贡献：第2位放500得50，第3位放300得60，第4位200得20，总130不够。所以 [300,500,400,200] 是字典序最大的可行序列，且无需修改。

### 样例 2

**输入**

```text
1
3
100 100 100
50 1
50 2
400
3
```

**输出**

```text
1
1000 100 100
```

**说明**

初始价格全为100，权重：位置1（50%），位置2（100%），位置3（50%）。最大可能捐赠：选三个100，排列为[100,100,100]得 50+100+50=200 <400，必须修改。可以修改一张票为1000，若放在位置2可得1000，位置1和3仍用100，总捐赠 100×50% + 1000×100% + 100×50% = 50+1000+50=1100 ≥400，仅修改1次。是否存在序列让修改1次时字典序更大？尝试把1000放在最前面：序列[1000,100,100] 位置1得500，位置2得100，位置3得50，总650≥400，且第一位置1000 > 100（其他方案第一位置最多100），故字典序最大。最少修改次数为1。输出方案。

## 说明

字典序比较：将价格序列 p'_1...p'_M 按位置顺序看作 M 位数，从左到右扫描，第一次出现数字不同的位置，数字大的序列字典序更大。总捐赠额计算可能超过 32 位整数范围，请使用 64 位整数。所有价格均为整百，捐赠额计算时直接除以 100 即可，不存在浮点误差。修改操作仅改变摊位上的商品标价，不改变商品本身，且修改后必须在 [100,10^9] 且是 100 的倍数。若一组查询无解，只输出一行 -1。
